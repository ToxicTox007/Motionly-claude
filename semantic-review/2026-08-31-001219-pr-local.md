# Local-audit isolation and live-effect gates

Task 2 combines a loopback Compose overlay with a plan-only preflight and runtime gates for selected model and publishing operations. The claimed default-deny boundary is incomplete: remote Runway and local-mode fallback calls skip the model gate, OAuth enrollment occurs before the publishing gate, and preflight can approve an env file different from the one Compose consumes. **Watch for:** **confirmed** default-deny does not cover all remote model calls; **confirmed** OAuth token exchange occurs before account and effects policy checks; **confirmed** inherited Compose variables can override a safe preflight env file.  
**Verdict**: NEEDS_CHANGES

## High-level view

The factory marks only its known HTTP adapters as remote. `create_app()` adds a Runway adapter afterwards with the default no-gate route flags, while local-mode fallback branches call Groq or OpenRouter without entering `ModelGateway`; external effects are not uniformly default-denied.

Publishing is gated before refresh, signed media access, and posting, but not while connecting an account. The callback exchanges live OAuth credentials and stores the connection before the policy runs, then publication trusts a caller-supplied account label rather than an identity bound to the token.

The overlay's static isolation is not made executable. Preflight inspects one env-file view, whereas Compose inherits shell variables and only receives a syntax check; a direct `up` does not require preflight success.

Sandbox labels, file secrets, and spend controls remain process-local assertions. They do not establish that a mounted credential belongs to the declared sandbox account, prevent its environment propagation, or preserve the aggregate ceiling across processes.

<summary>Issues (7)</summary>

1. **Critical — Runway and local-mode provider fallbacks bypass model authorization** (**confirmed**) — Mark every externally networked adapter, including the post-factory Runway route, as gate-required and fail closed for direct fallbacks in `LOCAL_AUDIT_MODE`. Support authorization for zero-cost remote polling rather than treating it as native.
2. **High — OAuth enrollment and connection metadata bypass publishing policy** (**confirmed**) — Gate the OAuth callback before exchange, validate the provider-returned account before persistence, and restrict caller-supplied token/account records in local-audit mode.
3. **High — A passing preflight can validate a different Compose runtime** (**confirmed**) — Run Compose with a sanitized environment derived from the checked env file, assert rendered isolation invariants, and require successful preflight from the runtime wrapper.
4. **High — Sandbox account declarations are not bound to provider credentials** (**likely**) — Use dedicated audit credentials and sandbox endpoints or provider identity validation; provider/account labels cannot distinguish production keys from sandbox keys.
5. **Medium — File-only audit authorization becomes a process-wide environment secret** (**confirmed**) — Validate mode and the exact mount before reading it, then use a non-environment settings source or `SecretStr` so subprocesses and environment diagnostics do not inherit the secret.
6. **Medium — The advertised total spend ceiling resets per process** (**confirmed**) — Store atomic reservations in a run-ID-scoped shared ledger so restart, scale-out, or a separate gateway instance cannot renew the ceiling.
7. **Medium — Protected-input validation does not constrain each secret file** (**confirmed**) — Resolve every required secret under the protected directory and outside the repository; replace the Windows display-name heuristic with an ACE/rights-based ACL check.

### Runway registration lands outside the remote adapter boundary

The gap is **confirmed** in `apps/api/app/main.py`, `apps/api/app/services/model_domain_adapters.py`, `apps/api/app/services/model_gateway_factory.py`, and `apps/api/app/services/model_gateway.py`. The factory binds endpoint metadata only on its initial known HTTP routes. `create_app()` later calls `register_runway_route()` for `RunwayGen3Provider`; that route has neither `endpoint_host` nor `requires_live_effects_gate`, so `ModelGateway.invoke()` does not call `authorize_model()` before `RunwayVideoGenerationAdapter` invokes the remote provider.

```text
factory HTTP route  -> endpoint binding -> gate-required -> gate -> adapter
Runway route added later -> default flags -----------------> adapter -> Runway HTTPS
```

The result is **confirmed**: a mounted `RUNWAY_API_KEY_FILE` can make a billable request when `LOCAL_AUDIT_EXTERNAL_EFFECTS_ENABLED=false` or the policy is invalid. The direct Groq transcription and OpenRouter planner fallbacks in `apps/api/app/main.py` are also **confirmed** bypass paths when a matching gateway route is absent; local-audit sets `APP_ENV=local`, enabling those non-production branches. A flag-only Runway fix would still fail for polling: `VideoGenerationPollRequest` has zero estimated cost, which `authorize_model()` rejects for a non-free route. Remote polling needs its own authorized state rather than being left outside the gate.

### OAuth connection establishment precedes the publishing gate

This is **confirmed** in `apps/api/app/api/publishing.py`, `apps/api/app/services/publishing.py`, and `apps/api/app/core/local_audit.py`. The new hook runs in `execute_publish_job()` and scheduled refresh, but `/publish/oauth/{platform}/callback` calls `PublishOAuthClient.exchange()` directly. The callback posts the authorization code and client credentials to TikTok, Meta, or Google, looks up the live account, and stores access/refresh tokens before effects policy or account allowlisting runs.

The later account check is also **confirmed** to be metadata-only. `PublishConnectionCreateRequest` accepts both `access_token` and `external_account_id`; `authorize_publish()` compares only that stored string with `LOCAL_AUDIT_PUBLISHING_ACCOUNTS`. A production token labeled `*-audit-*` passes the gate even though the provider determines the posting account from the token. Gate OAuth exchange by approved host, validate its returned identity before storage, and do not let manual token injection serve as an account assertion in audit mode.

### The preflight approves an env file, not necessarily the runtime

The Compose mismatch is **confirmed** in `apps/api/scripts/audit_local_capabilities.py`, `infra/docker-compose.local-audit.yml`, and `infra/local-audit/local-audit-compose.env.example`. `build_capability_report()` parses `--env-file` into `values` for policy checks, then `_compose_config_report()` launches `docker compose --env-file ... config -q` through `_run_command()` without `env=`. The child inherits its parent environment; Docker Compose resolves shell values ahead of env-file values, and the code observes only syntax success rather than rendered ports, domains, secrets, images, or the effects flag.

A safe env file can therefore report ready while inherited `LOCAL_AUDIT_EXTERNAL_EFFECTS_ENABLED`, `SECRETS_DIR`, domain, Sentry, or image values change the runtime. No code requires the standalone preflight before a direct Compose `up`, so accidental production domains, credentials, or telemetry remain possible despite the loopback overlay.

### Audit labels do not establish a sandbox credential identity

The production-credential risk is **likely** in `infra/docker-compose.local-audit.yml`, `apps/api/scripts/audit_local_capabilities.py`, and `apps/api/app/core/local_audit.py`. The overlay reuses the base `SECRETS_DIR`, including ordinary Groq, OpenRouter, Runway, and OAuth secrets; preflight only requires a private directory outside the repository.

For model calls, policy matches a declared provider name to a declared account, but adapters receive only API keys and no account identity. No code verifies the key belongs to the declared account or is sandbox-scoped. An `openrouter-audit-001` label can therefore pass while a production key reaches an approved public provider host. Dedicated audit credentials and sandbox endpoints are needed.

### The authorization file is read into inherited process state

The file-secret defect is **confirmed** in `apps/api/app/core/config.py`. `get_settings()` reads `LOCAL_AUDIT_EXTERNAL_AUTHORIZATION_FILE` before checking local-audit mode or the required `/run/secrets/local_audit_external_authorization` path, then writes its raw content to `os.environ["LOCAL_AUDIT_EXTERNAL_AUTHORIZATION"]`. Mount validation happens only later in the gate.

This turns the new file secret into a normal inherited environment value. The API spawns subprocesses, and logging redaction cannot remove a value already inherited by child processes or environment diagnostics. Validate before reading and retain the authorization only in an in-memory secret field.

### Spend reservations do not survive the process that made them

The spend-cap bypass is **confirmed** in `apps/api/app/core/local_audit.py`, `apps/api/app/main.py`, and `apps/api/app/services/model_gateway_factory.py`. Each `LocalAuditLiveEffectsGate` creates an `InMemoryLocalAuditSpendLedger`; it is not keyed or persisted by `LOCAL_AUDIT_RUN_ID`. Restarting the API, creating another gateway-bearing worker, or scaling creates a fresh `LOCAL_AUDIT_MAX_TOTAL_SPEND_USD` allowance. The Runway bypass does not reserve against this ledger at all.

### Individual secret files can escape the protected-input boundary

The secret-path gap is **confirmed** in `apps/api/scripts/audit_local_capabilities.py`. `_inspect_protected_inputs()` resolves `SECRETS_DIR`, then tests and reads `secret_directory / name` without resolving each required file or requiring it to remain under that directory and outside `ROOT`. A symlink can point at a repository file or another unintended location while the directory-level check reports the bundle as protected.

The Windows ACL verdict is **likely** bypassable: `_windows_acl_is_private()` accepts any `icacls` output without four English display-name substrings, without evaluating ACE permissions, inherited rights, SIDs, localized names, or other broad groups. Resolve and constrain every file or reject links/reparse points, and evaluate access rights rather than names.

### Local-audit tests miss the live boundary paths

The coverage gap is **confirmed** in `apps/api/tests/test_local_audit_capabilities.py`. The suite proves denial for a hand-built route explicitly marked `requires_live_effects_gate=True` and for `execute_publish_job()`. It does not exercise the registered Runway route, direct Groq/OpenRouter fallback, OAuth callback, manual-token connection path, inherited-variable Compose render, secret-link rejection, or restart-spend accounting. `python -m pytest tests/test_local_audit_capabilities.py tests/test_local_topology_audit.py -q` passed with 17 tests, so these paths are not covered.
